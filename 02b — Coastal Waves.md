# 02b — Coastal Waves: Shoreline, Foam, Breaking Waves, Wet Sand

### Companion to `00_ART_DIRECTION.md` (binding style contract) and `02_WATER.md` (open-water depth/colour model). `02_WATER.md` explicitly hands off shoreline foam/break waves to this doc and defines its own `uBathymetry` texture (R: 0 = shoreline, 1 = abyssal) for the open-sea depth-colour ramp. This doc's shore atlas (§1) is the **nearshore companion** to that bathymetry map, covering the same physical strip (0–60 m from shore) at higher resolution and adding the distance/normal/exposure signals bathymetry alone doesn't carry — both should be baked from the same island heightmap pass so they never disagree.

> **Style contract reminder (from `00_ART_DIRECTION.md`):** foam, glints, and spray are *painted hard-edged white shapes* — dashes, ovals, stepped bands — never soft round particle puffs, never a Gaussian-blurred alpha falloff. Shadow tones are hue-shifted, not darkened. The shelf/shore transition is a **visible band edge**, not a blur. Every technique below is chosen and parameterized to produce **stepped, quantised, cel-shaped** results, even where the underlying research technique (Unity/Unreal/Shadertoy) defaults to soft, continuous blending.

---

## 1. Coastline SDF / shore-distance map

### 1.1 What to bake

For every island (or island cluster within one atlas tile) bake a 2–4 channel texture in the island's local top-down UV space:

| Channel | Content | Range / encoding |
|---|---|---|
| R | Signed distance to shoreline (negative = under land, positive = under water) | Encode as `0.5 + dist / maxDist * 0.5`, `maxDist` ≈ 60 m |
| G | Depth below sea level (0 at shore, increasing seaward), derived from the island heightmap | `saturate(depth / depthFalloff)`, `depthFalloff` ≈ 12–20 m |
| B | Shore-normal angle (2D, packed) or split into a second RG texture if precision matters | `atan2` packed to 0–1 |
| A | Coastline curvature / exposure mask (convex headland vs. sheltered cove) — cheap proxy for wave-energy weighting | 0 = sheltered cove, 1 = exposed headland |

This is the pattern used by Blend4Web's baked **Shore Distance Map** — select landscape + water meshes and bake to a texture sized to the water tile, with an artist-set "maximum distance to shore" ([Blend4Web Outdoor Effects docs](https://www.blend4web.com/doc/en/outdoor_rendering.html)). Unity's Roystan toon-water tutorial uses the same idea but derives it at runtime from the camera depth buffer instead ([Roystan, "Unity Toon Water Shader Tutorial"](https://roystan.net/articles/toon-water/)).

**Why bake an SDF instead of using runtime depth-buffer comparison:** the camera here sits at 200–1500 m and can view any island from any azimuth, including near-vertical. A camera-depth-buffer "edge foam" trick only detects intersections in the current view frustum and breaks down at steep top-down angles or when foam should be visible on an island's far side — the failure mode flagged in the three.js forum's unlit-water-with-foam thread ([three.js forum, "Unlit water shader with foam"](https://discourse.threejs.org/t/unlit-water-shader-with-foam/11641)). A pre-baked world-space SDF has no such view dependency.

### 1.2 Baking pipeline (runtime, for procedural islands)

Because islands are procedurally generated, baking happens once per island at spawn/streaming-in time, not per frame:

1. Rasterize the island heightmap (already generated by `03_ISLANDS.md`'s pipeline) to an offscreen `WebGLRenderTarget`.
2. Run a **jump-flood / multi-pass distance transform** shader over that render target: seed pixels at the 0-elevation contour, then iterate `log2(N)` passes of jump-flooding to propagate nearest-seed distance and direction. This is the standard GPU JFA approach used for real-time 2D/3D SDFs and is exactly what Unreal's global distance field (`DistanceToNearestSurface` node) does under the hood, just pre-baked per-island here instead of scene-global ([Unreal Engine Forums, "Distance field based foam for water shader"](https://forums.unrealengine.com/t/distance-field-based-foam-for-water-shader/133034)).
3. Derive the depth channel directly from the heightmap (it's already in hand — no extra pass needed beyond a remap/clamp).
4. Derive the shore-normal from the distance field's gradient (central-difference on the R channel) rather than storing it separately if memory is tight — saves a channel at the cost of one extra `textureLod` sample pair in the water shader.
5. Store the result as a `RGBA8` texture (SDF/depth typically don't need float precision at this range — 8-bit is enough given the hard, stepped look we want anyway).

### 1.3 Resolution and memory budget

| Island size (footprint) | Atlas resolution | Memory (RGBA8) | Notes |
|---|---|---|---|
| Small islet (≤200 m across) | 256×256 | 256 KB | Most Adriatic karst islets in this world |
| Medium island (200–800 m) | 512×512 | 1 MB | Typical harbour-town island |
| Large island (800–2000 m) | 1024×1024 | 4 MB | Rare "hero" islands |

Budget target: **≤ 16 MB total** for shore-distance atlases across all currently-loaded islands, consistent with the terrain/ocean triangle-and-drawcall budget already set in `00_ART_DIRECTION.md` §5. At 8-bit RGBA and these sizes, even 8–10 simultaneously-resident medium islands stay under 10 MB. Pack multiple small islets into a single shared atlas page (simple grid or shelf-packed) to cut draw-call/texture-bind overhead, mirroring how the terrain pipeline already budgets ≤ 40 draw calls.

### 1.4 Runtime updates for procedural islands

- **Bake once, cache to disk/IndexedDB** keyed by island seed — a JFA pass for a 512² texture is cheap, no need to redo it every session if the seed hasn't changed.
- **Streaming budget:** spread the jump-flood passes for a newly streamed-in island over 2–4 frames (one pass/frame) rather than stalling on load.
- **Static islands only need this once.** If terrain deformation is added later, re-bake only the affected atlas tile, not the whole world.

## 2. Foam bands

### 2.1 Two layers: static ring + animated run-up

Split foam into two additive layers, matching the two-part decomposition used across nearly every stylized-water breakdown surveyed (Unity toon water, Unreal Nimue, Cyanilux):

1. **Static shoreline foam ring** — a thin band clamped to a narrow SDF range (distance ∈ [0, 1.5 m]), constant intensity, representing perpetual foam clinging to rock/sand at the waterline. Cheap: one `smoothstep` on the R channel of the shore atlas.
2. **Animated wave-run-up band** — a wider band (distance ∈ [0, 8–15 m], scaled by exposure/curvature channel A) driven by a **repeating sawtooth phase** so foam visibly surges landward then retreats, rather than a static gradient. Cyanilux's shoreline breakdown builds a "gradient towards shore," offsets it by `time * scrollSpeed`, periodically repeats it with `frac`/`cosine`, then adds a second synced cosine-driven swash term for the back-and-forth motion of the leading edge ([Cyanilux, "Shoreline Shader Breakdown"](https://www.cyanilux.com/tutorials/shoreline-shader-breakdown/)). The oneiricworlds write-up arrives at the same core formula independently: `sin(frequency * v + speed * time)`, clipped at a threshold, `v` being the shore-direction coordinate ([oneiricworlds, "Semi-procedural foam shader"](https://oneiricworlds.com/en/2019/01/cartoonish-foam-using-procedural-hand-made-textures/)).

**Sawtooth, not sine, for this project.** A pure sine run-up looks symmetrical, but real swash surges fast and retreats slow. Use `frac(time * runupSpeed - shoreDist * runupFreq)` fed through a sharp `smoothstep` for the leading edge, plus a separate slower-decaying trailing edge — the asymmetry the Babylon.js beach-viewer discussion converged on when a symmetric approach looked too mechanical ("receding foam ... washes back out before being pushed by the next wave") ([Babylon.js forum, "Suggestions for creating realistic surf and waves crashing on a beach"](https://forum.babylonjs.com/t/suggestions-for-creating-realistic-surf-and-waves-crashing-on-a-beach/58664)).

### 2.2 Stepped/quantised edges — the Ghibli requirement

Every source surveyed defaults to `smoothstep` alone for soft antialiased edges. **Override this.** Per the art bible's "stepped tonal bands, not smooth gradients" rule, run the foam mask through a **quantising step function** after the smoothstep:

```glsl
float quantizeFoam(float x, float steps) {
    float s = smoothstep(0.0, 1.0, x);       // antialias the raw edge only
    return floor(s * steps) / steps;          // then collapse to N flat bands
}
```

With `steps = 3.0` this gives exactly the "3–6% of sea pixels, discrete dashes" look the art bible specifies for wave-crest highlights, applied here to foam. Keep one `smoothstep` of ~1–2 px width purely for edge antialiasing (never let foam edges hard-crawl/shimmer at distance), then quantise on top — soft-edge-then-quantise, not raw-step, avoids moiré.

### 2.3 Foam texture vs. procedural noise thresholding

Sea of Thieves blends *both*: a procedurally generated foam mask (FFT choppiness / depth-intersection) is progressively blurred, then **blended with artist-authored textures for a more stylized appearance**, with calm vs. stormy states swapping blend recipes ([SIGGRAPH 2018, "The Technical Art of Sea of Thieves"](https://history.siggraph.org/wp-content/uploads/2022/09/2018-Talks-Ang_The-Technical-Art-of-Sea-of-Thieves.pdf)). For this project's painted style, prefer a **hand-painted foam alpha texture** (tileable strip of blobby cel-shaped clumps, hard edges, not photographic) tiled along the shore-direction UV, with procedural noise used only to break up *positional* repetition — never to soften edges. This matches oneiricworlds' recipe: `ratioSinus * proceduralWave + ratioTex * paintedTexture`, clipped at threshold `t` ([oneiricworlds](https://oneiricworlds.com/en/2019/01/cartoonish-foam-using-procedural-hand-made-textures/)).

### 2.4 Sub-pixel behaviour: altitude vs. low pass

| Camera state | Foam band behaviour |
|---|---|
| High altitude (600–1500 m) | Collapse both foam layers into a **single flat-shaded coastline stroke** — a 2–4 px constant-width white line following the SDF zero-contour, no animation (it will alias into noise otherwise). Fade run-up band out entirely past ~600 m; keep only the static ring. |
| Mid altitude (150–600 m) | Full two-layer system, animated, quantised to 3 bands. |
| Low pass / near water (<150 m) | Add a third fine-detail layer: high-frequency painted foam clumps + optional per-quad crest ribbons (§3). This is the only regime where individual foam clumps should be legible as shapes rather than a band. |

Drive the transition with a single `foamDetailLOD = smoothstep(600.0, 150.0, cameraDistanceToShore)` uniform, computed CPU-side per visible island, not per pixel.

## 3. Breaking waves

### 3.1 The physics you're stylizing

As a wave train travels from open water toward the coast, decreasing depth slows the wave (shoaling) and — where the seabed contour is not parallel to the wave front — bends the crest to align more with the depth contours (refraction), which is why waves visibly curve to face the beach even when arriving at an angle offshore. Wave height also increases as depth decreases up to the point where the wave becomes unstable and breaks ([Coastal Dynamics textbook, §5.2.3 "Refraction"](https://geo.libretexts.org/Bookshelves/Oceanography/Coastal_Dynamics_%28Bosboom_and_Stive%29/05:_Coastal_hydrodynamics/5.02:_Wave_transformation/5.2.3:_Refraction); [CoastalWiki, "Shallow-water wave theory"](https://www.coastalwiki.org/wiki/Shallow-water_wave_theory)). The art takeaway: **crest lines should visibly bend to run roughly parallel to the shore SDF's iso-contours as depth (channel G) drops below ~3–4 m**, with crest amplitude/whiteness ramping up over that same range, peaking at the break point before collapsing into foam.

### 3.2 Three approaches, and how to combine them

| Approach | What it is | Cost | Best for |
|---|---|---|---|
| (a) Shader-only fake break | Vertex-displace a shore-fringe strip of the water mesh using a sawtooth/noise wave function keyed to shore-distance and depth (channel G), whiten via a threshold on displacement steepness | Very low — no extra geometry, one extra vertex shader term | Default for all coastline, all distances |
| (b) Animated crest meshes/ribbons | A thin ribbon mesh generated along the coastline spline (same spline `03_ISLANDS.md` uses to build the shore), swept with a scrolling UV and a per-segment phase offset so crests appear to travel along the beach and arrive slightly staggered | Medium — one extra draw call per visible island, low triangle count (a ribbon is a handful of quads wide) | Exposed headlands / hero coves in mid-to-low altitude shots |
| (c) Particle spray on rocks | Sparse, camera-facing billboard bursts fired where a wave-phase event coincides with a rock/cliff SDF hit | Medium-low if pooled and capped | Rocky coastlines only, low altitude |

**Recommendation: layer (a) everywhere as the base, add (b) only for hero/foreground coastline segments selected by camera distance, and reserve (c) for rock/cliff contact points specifically (§4).** This mirrors the layered structure Wind Waker used for its shoreline lapping — "several layers working together... carefully-timed animation creating the impression of natural wave movement" — and Sea of Thieves' layered normal-map + choppiness-mask approach, scaled down to this game's flatter painterly needs ([Zelda Dungeon, "Detailed Technical Analysis of Wind Waker's Water"](https://www.zeldadungeon.net/watch-this-detailed-technical-analysis-of-wind-wakers-water/); [SIGGRAPH 2018 Sea of Thieves talk](https://history.siggraph.org/wp-content/uploads/2022/09/2018-Talks-Ang_The-Technical-Art-of-Sea-of-Thieves.pdf)).

Cyanilux's "UV-based shoreline" mesh strip — a ribbon of quads along the coast, UV-unwrapped with **Follow Active Quads** so V runs from sea (0) to sand (1) — is the direct three.js-portable version of approach (b); build the ribbon procedurally from the coastline spline instead of hand-modeling it ([Cyanilux, "Shoreline Shader Breakdown"](https://www.cyanilux.com/tutorials/shoreline-shader-breakdown/)).

### 3.3 LOD by camera distance

| Distance to shore (camera) | Active layers |
|---|---|
| > 600 m | (a) only, flattened, static coastline stroke (see §2.4) |
| 150–600 m | (a) + (b) for the ≤3 nearest/largest visible coastline segments only |
| < 150 m | (a) + (b) + (c), full detail |

Cap (b) ribbon segment count globally (e.g. ≤ 6 active ribbons across all islands) and recycle the pool as the camera moves — the same "grid system that spawns high-res plane meshes... and low-res... around that" LOD pattern used in the Nimue UE5 water breakdown ([80.lv, "How to Build Stylized Water Shader — Nimue"](https://80.lv/articles/how-to-build-stylized-water-shader-design-implementation-for-nimue)).

## 4. Rocks and cliffs meeting water

### 4.1 Timing to swell phase, not per-frame noise

Spray bursts must read as **discrete events**, not continuous mist. Drive each rock-contact emitter from the same run-up sawtooth phase used for foam (§2.1): trigger a burst when local wave phase crosses a threshold near its peak, with a small random per-rock delay (0.1–0.4 s) so a cluster of rocks doesn't burst in unison — consistent with the art bible's "discrete highlights, not specular blobs" rule.

### 4.2 Cheap billboard sprites, cel-shaped alpha — not soft puffs

Use camera-facing (or up-axis-locked, camera-yaw-only) billboard quads with a **hand-painted, hard-edged alpha mask**: 4–6 unique burst shapes (asymmetric splash silhouettes, not circles), thresholded rather than radially soft, so it reads as a painted ink-splatter rather than a smoke particle — avoiding the default "soft round particle" look the art bible explicitly forbids ("foam is painted hard-edged white shapes not particles-mush"). Author sprite alpha with a `step()`-like edge baked into the texture, and clip again in-shader with `alphaTest` (or `if (alpha < 0.5) discard;`) so no soft edge survives blending.

Pool sprites (16–32 live instances max), use a single `InstancedMesh` of camera-facing quads, animate scale-up/fade via a per-instance age attribute, and cull by distance to shore-SDF rock mask.

### 4.3 Recommended parameters

| Parameter | Starting value |
|---|---|
| Burst lifetime | 0.6–1.0 s |
| Burst max scale | 1.5–4 m (varies with exposure channel A — bigger on exposed headlands) |
| Random delay per rock | 0.1–0.4 s |
| Max concurrent bursts (global) | 24 |
| Alpha cutoff | 0.5 (hard `alphaTest`) |

## 5. Wet sand, translucent shallows, tide-line residue

- **Wet sand darkening band:** a second, wider SDF band (distance ∈ [0, ~20 m] landward) that darkens and desaturates sand albedo — shift beach sand `#cbc5ad`/`#ddd0a8` (per `00_ART_DIRECTION.md` §2) toward `#8f8874`-ish, hue-shifted cool, never a flat multiply (extending the art bible's shadow rule to "wet" tone shifts). Modulate its extent by the run-up phase so it grows/shrinks with each swash cycle, matching the "wet-sand shape should mirror the last wave" logic from the Babylon.js beach prototype discussion ([Babylon.js forum](https://forum.babylonjs.com/t/suggestions-for-creating-realistic-surf-and-waves-crashing-on-a-beach/58664)).
- **Translucent turquoise shallows over sand:** squarely `02_WATER.md`'s domain (shelf-band transition `#074d5c` → `#14707c` → `#498e8e`/`#309dac`/`#62afb4`). This doc doesn't redefine it — only requires the shore atlas's depth channel (G) to be the *same* signal feeding that shelf-band lookup, so the two systems never disagree about where "shallow" starts. Reuse `02_WATER.md`'s depth-to-colour ramp/LUT directly.
- **Tide-line residue:** a thin, mostly-static high-water mark 1–3 m landward of the wet-sand band — a scatter of darker dashes (seaweed/debris silhouettes, 3–5 painted shape variants, not noise) placed via a stable hash of world position along the coastline spline so it doesn't swim frame to frame. Uses the same spline arc-length coordinate as the foam ribbon UVs (§3.2) for consistent placement.

## 6. Sound/feel hooks (optional)

Trigger surf audio purely from the shore-distance signal already resident on the CPU side (the same data used to place foam ribbons), not from a separate audio-specific raycast:

- Maintain a small set of "surf emitter" points per visible island, seeded along the coastline spline at fixed arc-length intervals (e.g. every 40–80 m, denser on exposed/high-curvature stretches using channel A).
- Volume/intensity scales with the exposure channel A and with camera proximity; pitch/density of surf "hiss" layer increases slightly during the peak of the run-up sawtooth phase so audio subtly syncs to the visual surge.
- Crossfade to a generic ambient "distant surf" bed once the nearest emitter exceeds ~250 m, to avoid discrete-emitter phasing artifacts at altitude.

## 7. Performance and integration

### 7.1 Pipeline attachment point

The shoreline system is a **post-process stage of the island generation pipeline** (`03_ISLANDS.md`), not a separate authoring pass:

1. Island heightmap generated →
2. Coastline contour + spline extracted (needed anyway for beach placement, road/harbour siting) →
3. Shore-distance atlas baked (§1.2), keyed to same UV space as terrain material →
4. Foam ribbon geometry (§3.2b) and rock-spray emitter points (§4) generated from the same spline, cached with the island →
5. Water shader for tiles adjacent to this island samples the atlas.

This means shoreline data has *zero* extra runtime generation cost beyond the one-time atlas bake — it rides on data the island pipeline produces anyway.

### 7.2 Budget table

| Resource | Budget | Notes |
|---|---|---|
| Shore-distance atlas memory | ≤ 16 MB total resident | §1.3 |
| Foam ribbon draw calls | ≤ 6 concurrent, instanced/batched where possible | §3.3 |
| Rock-spray sprite instances | ≤ 24–32 concurrent, single `InstancedMesh` | §4.3 |
| Extra triangles (ribbons) | ≤ 5k tris total across all active ribbons | Thin strips, low segment count |
| Fits inside | The existing "ocean + sky + 3 visible islands ≤ 1.2M triangles, ≤ 40 draw calls" ceiling from `00_ART_DIRECTION.md` §5 | Shoreline adds ≤ 10 draw calls and negligible triangles against that ceiling |

### 7.3 What happens for 3+ visible islands

- **Atlas sharing:** islands with only a small on-screen footprint share a packed atlas page rather than each owning a full-resolution texture; drop resolution tier (§1.3) by projected screen size, recomputed on visible-island-set change, not per frame.
- **Ribbon budget is global, not per-island.** With the ≤6 concurrent ribbon cap, ribbons go to the coastline segments with smallest camera distance and highest exposure value first; islands beyond the top N get static-band-only foam (§2.4's high-altitude behaviour) regardless of actual altitude.
- **Rock-spray emitters degrade gracefully:** the global 24–32 sprite cap is shared; emitters skip their trigger if the pool is exhausted rather than queuing.
- **Static foam ring (§2.1 layer 1) is always-on and cheap regardless of island count** — one texture sample and quantize, never needs to degrade.

## 8. Three.js code sketches

### 8.1 Shore-distance atlas: JFA bake pass (fragment shader, run N=log2(size) times)

```glsl
// jfa_pass.frag — one iteration of jump-flood; ping-pongs between two render targets
precision highp float;
uniform sampler2D uSeedTex; // rgba: xy = nearest seed pos (encoded 0-1), .z = valid flag
uniform vec2 uTexel;
uniform float uStepPixels; // halves each pass: size/2, size/4, ... 1
varying vec2 vUv;

vec4 sampleAt(vec2 uv) { return texture2D(uSeedTex, uv); }

void main() {
  vec4 best = sampleAt(vUv);
  float bestDist = best.z > 0.5 ? distance(vUv, best.xy) : 1e6;
  for (int oy = -1; oy <= 1; oy++) {
    for (int ox = -1; ox <= 1; ox++) {
      if (ox == 0 && oy == 0) continue;
      vec2 offs = vec2(float(ox), float(oy)) * uStepPixels * uTexel;
      vec4 cand = sampleAt(vUv + offs);
      if (cand.z > 0.5) {
        float d = distance(vUv, cand.xy);
        if (d < bestDist) { bestDist = d; best = cand; }
      }
    }
  }
  gl_FragColor = best;
}
```

### 8.2 Packing distance + depth + exposure into the shore atlas (final composite pass)

```glsl
// shore_atlas_compose.frag
uniform sampler2D uJFAResult;   // nearest-seed encoded position
uniform sampler2D uHeightmap;   // island heightmap, R = elevation (sea level = 0.5)
uniform float uMaxShoreDist;    // e.g. 60.0 m
uniform float uDepthFalloff;    // e.g. 16.0 m
varying vec2 vUv;

void main() {
  vec4 seed = texture2D(uJFAResult, vUv);
  float dist = distance(vUv, seed.xy) * uAtlasWorldSize; // world units
  float elevation = (texture2D(uHeightmap, vUv).r - 0.5) * uHeightScale;
  float signedDist = elevation >= 0.0 ? -dist : dist; // land negative, sea positive
  float depth = clamp(-elevation, 0.0, uDepthFalloff) / uDepthFalloff;
  float rEnc = 0.5 + clamp(signedDist / uMaxShoreDist, -1.0, 1.0) * 0.5;
  gl_FragColor = vec4(rEnc, depth, 0.0, 1.0); // exposure (A) filled in a separate CPU-driven pass
}
```

### 8.3 Foam sampling + quantised run-up in the water fragment shader

```glsl
uniform sampler2D uShoreAtlas;
uniform float uTime;
uniform float uRunupSpeed;     // ~0.6
uniform float uRunupFreq;      // ~0.12 (per metre)
uniform float uFoamSteps;      // 3.0
uniform float uFoamDetailLOD;  // 0 (far) .. 1 (near), CPU-set per island

float quantizeFoam(float x, float steps) {
  float s = smoothstep(0.0, 1.0, x);
  return floor(s * steps) / steps;
}

vec3 shoreFoam(vec2 shoreUV, vec3 baseColor, vec3 foamColor) {
  vec4 shore = texture2D(uShoreAtlas, shoreUV);
  float signedDist = (shore.r - 0.5) * 2.0 * uMaxShoreDist; // metres, +sea / -land
  float depth = shore.g;

  // Static ring: tight band right at the waterline.
  float staticRing = 1.0 - smoothstep(0.0, 1.5, abs(signedDist));

  // Animated run-up: sawtooth ramp landward, sharper leading edge than trailing.
  float phase = fract(uTime * uRunupSpeed - signedDist * uRunupFreq);
  float leading  = smoothstep(0.85, 1.0, phase);
  float trailing = smoothstep(0.55, 0.0, phase) * 0.5;
  float runup = max(leading, trailing) * smoothstep(12.0, 0.0, signedDist); // fades by 12m out

  float foamRaw = max(staticRing, runup * uFoamDetailLOD);
  float foamMask = quantizeFoam(foamRaw, uFoamSteps);

  return mix(baseColor, foamColor, foamMask);
}
```

### 8.4 Rock-spray billboard burst (InstancedMesh, minimal sketch)

```js
// RockSprayBursts.js
import * as THREE from 'three';

const MAX_BURSTS = 32;
const geo = new THREE.PlaneGeometry(1, 1);
const mat = new THREE.MeshBasicMaterial({
  map: rockSprayAtlasTexture, // hand-painted, hard-edged alpha, 4-6 variants tiled in atlas
  transparent: true,
  alphaTest: 0.5,             // hard cutoff — no soft particle edge
  depthWrite: false,
});
const bursts = new THREE.InstancedMesh(geo, mat, MAX_BURSTS);
bursts.instanceMatrix.setUsage(THREE.DynamicDrawUsage);

const state = Array.from({ length: MAX_BURSTS }, () => ({ active: false, age: 0, life: 0.8, pos: new THREE.Vector3(), scale: 2.0 }));

function triggerBurst(pos, scale = 2.0, life = 0.8) {
  const slot = state.find(s => !s.active);
  if (!slot) return; // pool exhausted — skip, don't queue
  Object.assign(slot, { active: true, age: 0, life, pos: pos.clone(), scale });
}

function update(dt, camera) {
  const m = new THREE.Matrix4();
  state.forEach((s, i) => {
    if (!s.active) { m.makeScale(0, 0, 0); bursts.setMatrixAt(i, m); return; }
    s.age += dt;
    if (s.age >= s.life) { s.active = false; m.makeScale(0, 0, 0); bursts.setMatrixAt(i, m); return; }
    const t = s.age / s.life;
    const scale = s.scale * THREE.MathUtils.lerp(0.3, 1.0, Math.min(t * 3.0, 1.0)); // fast scale-up
    m.compose(s.pos, camera.quaternion, new THREE.Vector3(scale, scale, scale)); // camera-facing (yaw-locked variant: strip pitch/roll from quaternion)
    bursts.setMatrixAt(i, m);
  });
  bursts.instanceMatrix.needsUpdate = true;
}
```
